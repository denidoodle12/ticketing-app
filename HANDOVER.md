## 5. New Developer Machine Setup

### Software Prerequisites
- **Flutter SDK** ≥ 3.9.2 (stable channel). Check with `flutter --version`.
- **Android Studio** (for the Android SDK + emulator).
- **Android NDK** version `27.0.12077973` (matches `build.gradle.kts`). Install via Android Studio → SDK Manager → SDK Tools → NDK (Side by side).
- **Firebase CLI** for deploys: `npm install -g firebase-tools`.
- **Java 11+** (already bundled with Android Studio's JDK).
- **Git** + access to the internal remote.

### Step-by-step Setup
```bash
# 1. Clone
git clone <enigma-remote-url> ticketing_app
cd ticketing_app

# 2. Drop in the credential files (see docs/CREDENTIALS_HANDOVER.md)
# - android/key.properties
# - android/app/google-services.json

# - android/local.properties
# - android/app/src/main/jni/curl/  (prebuilt folder)
# - android/app/src/main/jni/rapidjson/  (header folder)
# - assets/certs/cacert.pem

# 3. Install dependencies
flutter pub get

# 4. Login Firebase (for deploy)
firebase login

# 5. Verify a debug build
flutter build apk --debug

# 6. Verify a release (signed) build
flutter build apk --release

# 7. (Optional) Smoke-test deploying to App Distribution
.\deploy.bat "smoke test from new dev machine"
```

- [ ] `flutter analyze` → `No issues found`

## 6. Build & Deploy Workflow

### Debug Build (everyday development)
```bash
flutter run
# or
flutter build apk --debug
```

### Release Build (for QA / production)
```bash
flutter build apk --release
# Output: build/app/outputs/flutter-apk/app-release.apk
```

> [!IMPORTANT]
> Release builds **require** a valid `key.properties`. Without it the build falls back to the debug keystore → the APK will **fail signature verification** and show `SecurityErrorScreen` at launch.

### Build With Backend Override
```bash
# Default = production
flutter build apk --release

# Staging
flutter build apk --release --dart-define=API_BASE_URL=https://magang.damarbrawijaya.my.id
```

### AAB Build for Play Store (when publishing eventually)
```bash
flutter build appbundle --release
# Output: build/app/outputs/bundle/release/app-release.aab
```

### Deploy to Firebase App Distribution
**Quick way (recommended):**
```bash
.\deploy.bat "short release notes here"
```

`deploy.bat` does the following:
1. Reads the version from `pubspec.yaml`
2. Runs `flutter build apk --release`
3. Uploads to Firebase App Distribution targeting the `enigma-ticketing-app` tester group

**Manual way:**
```bash
flutter build apk --release
firebase appdistribution:distribute \
  build/app/outputs/flutter-apk/app-release.apk \
  --app 1:866621809782:android:34d880d6e90da18c93eb57 \
  --groups "enigma-ticketing-app" \
  --release-notes "Your release notes here"
```

### Bump Version
Edit `pubspec.yaml`:
```yaml
version: 0.16.0+16   # format: <semver>+<buildNumber>
```
- `<semver>` → shown in the app and release notes
- `+<buildNumber>` → optional, used for unique-per-upload identifiers in Play Store

## 7. Signature Checker — Maintenance Critical

> [!WARNING]
> This section is **the most sensitive** part of the project. A bad update here will immediately show `SecurityErrorScreen` to every user, requiring a rebuild and redeploy.

### What It Is
Files: `lib/core/security/signature_checker.dart` and `android/app/src/main/jni/security/signature_checker.cpp`.

The logic: native C++ reads the APK using raw syscalls (Frida-resistant), extracts the certificate from `META-INF/`, computes a SHA-256, and compares it with the **expected hash** baked into `libjavaloader.so` at build time.

### When To Update The Hash
**Only when the keystore changes.** That is:
- Replacing `Enigma.p12` (lost, expired, or rotated by policy)
- Generating a new keystore for any reason

### How To Update The Hash (Keystore Rotation)

1. **Generate a new keystore** (or get one from the security team):
   ```bash
   keytool -genkey -v -keystore Enigma.p12 -storetype PKCS12 \
     -keyalg RSA -keysize 2048 -validity 10000 -alias enigma
   ```

2. **Compute the SHA-256 of the certificate:**
   ```bash
   keytool -list -v -keystore Enigma.p12 -storetype PKCS12 -alias enigma
   # Look for the line "SHA256: XX:XX:XX..."
   # Strip the colons and lowercase. Example: 6a3b5c...
   ```

3. **Update the expected hash in the native code:**
   File: `android/app/src/main/jni/security/signature_checker.cpp` (or a related header).
   Find the hardcoded hash constant → replace it with the new one. The hash is obfuscated to make it harder for reverse engineers to find.

4. **Rebuild the native lib + APK:**
   ```bash
   flutter clean
   flutter pub get
   flutter build apk --release
   ```

5. **Verify:**
   ```bash
   apksigner verify --print-certs build/app/outputs/flutter-apk/app-release.apk
   # The SHA-256 must match what is in the native code
   ```

6. **Install on a test device → it must boot to the home screen, not `SecurityErrorScreen`.**

> [!CAUTION]
> If the APK is signed with keystore A but the native code expects the hash from keystore B, the app will refuse to boot. **Always test on a device before pushing to the tester group.**

### Temporarily Disable (Emergency Only)
If you urgently need to skip the check (for example while debugging an unrelated problem):

`lib/main.dart`:
```dart
// Comment this block out:
// if (Platform.isAndroid) {
//   if (!SignatureChecker.verify()) {
//     runApp(const SecurityErrorScreen());
//     return;
//   }
// }
```

> [!WARNING]
> **Do not commit this change to `master` or `dev`.** It is for local debugging only. Production builds must always have the check enabled.

## 10. Native C++ Code (SSE & Signature)

### Native Files
```
android/app/src/main/jni/
├── Android.mk
├── Application.mk
├── javaloader.cpp                  # FFI entry point
├── sse/
│   └── sse_client.cpp              # SSE long-polling via libcurl
├── security/
│   └── signature_checker.cpp       # APK signature verification
├── helpers/
│   ├── ApkHelper.cpp
│   ├── ZipHelper.cpp
│   └── SysCalls.cpp                # Raw syscalls (bypass libc hooks)
├── curl/                           # Prebuilt static libs (OFF-REPO)
└── rapidjson/                      # Header-only JSON (OFF-REPO)
```

### Re-applying On A Fresh Machine
**Required reading:** [docs/NATIVE_SSE_SETUP.md](./docs/NATIVE_SSE_SETUP.md). It is the complete guide for:
- Setting `ndk.dir` in `local.properties`
- Dropping the `curl/` and `rapidjson/` folders into the right location
- Configuring the Gradle ndk-build task
- Troubleshooting common errors (CXX1400, CURLcode 60, etc.)

### Native Build
The `ndkBuildNative` task is triggered automatically by `flutter build`. Output: `android/app/src/main/jniLibs/<abi>/libjavaloader.so`.

### Verification
```bash
# Confirm the .so is included in the APK
Expand-Archive build\app\outputs\flutter-apk\app-release.apk -DestinationPath build\apk-extracted -Force
Get-ChildItem build\apk-extracted\lib -Recurse -Filter libjavaloader.so

# Monitor native logs at runtime
adb logcat JavaLoader:V flutter:V *:S
```

## 11. Common Maintenance Scenarios

### Swap Backend URL
1. Edit `lib/core/constants/api_config.dart` → change `defaultValue`.
2. Or use `--dart-define=API_BASE_URL=...` at build time (no code change).

### Update Firebase App Distribution Testers
1. Firebase Console → App Distribution → Testers & Groups.
2. Edit the `enigma-ticketing-app` group → add/remove emails.

### Bump App Version
Edit `pubspec.yaml`:
```yaml
version: 0.17.0
```

### Add an Android Permission
Edit `android/app/src/main/AndroidManifest.xml` — add a `<uses-permission ... />`. The current permission list is in [PROJECT_DOCUMENTATION.md Section 20](./PROJECT_DOCUMENTATION.md#20-android-permissions).

### Rotate the Keystore
See [Section 7 — Signature Checker](#7-signature-checker--maintenance-critical) above.

### Add a Dependency
1. Edit `pubspec.yaml`.
2. Run `flutter pub get`.
3. Run a release build → check there are no new ProGuard warnings. If there are, add rules in `android/app/proguard-rules.pro`.

### Update Firebase Config
1. Firebase Console → Project Settings → Your Apps → download a fresh `google-services.json`.
2. Replace `android/app/google-services.json`.
3. Run `flutterfire configure` to regenerate `lib/firebase_options.dart`.

## 13. Notes & Known Issues

### Things Worth Knowing
- **Two Dio instances** in `dio_client.dart` (`authInstance` and `userInstance`) — they currently share the same base URL. This is set up so a future gateway split is easy.
- **Token mutex** in `TokenRefreshService` — if you see a 401 storm, check the `_isRefreshing` flag first.
- **Notifications use SSE rather than FCM** — FCM is initialized for the future, but the primary trigger is the foreground service.
- **The background isolate has its own `SharedPreferences`** for the SSE token — synchronized via `service.invoke('updateToken', ...)`.

### Active Known Issues
- The knowledge tag filter returns 0 results on the production backend (backend bug, already tracked).
- iOS has not been verified end-to-end (folder exists but is not yet published).

### Edge Cases Already Handled
See [PROJECT_DOCUMENTATION.md Section 23](./PROJECT_DOCUMENTATION.md#23-known-issues--edge-cases) for the full list.

### Performance & Profiling

```bash
flutter run --profile          # check for frame jank
flutter run --trace-startup    # check startup time
```
